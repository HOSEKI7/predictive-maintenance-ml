# Predictive Maintenance — Failure Classification & Anomaly Detection

End-to-end predictive maintenance system using the AI4I 2020 sensor dataset. Two-layer detection: **XGBoost** for failure classification + **Isolation Forest** for unsupervised anomaly detection, deployed as an interactive **Streamlit** dashboard.

## Problem

Industrial equipment failures cause unplanned downtime and high maintenance costs. This project simulates a real-time predictive maintenance system that monitors sensor readings (temperature, rotational speed, torque, tool wear) and provides early warnings through a risk-level dashboard.

## Dataset

**AI4I 2020 Predictive Maintenance Dataset** — 10,000 rows, 14 columns.

| Feature | Description |
|---------|-------------|
| Air temperature | Generated by random walk, normalized to [K] |
| Process temperature | Similar random walk, always ≥ air temp |
| Rotational speed | Range ~1168–2886 rpm |
| Torque | Range ~3.8–76.6 Nm, proxy for electrical load |
| Tool wear | Minutes of operation, accumulates |
| Type | Product quality variant (L / M / H) |

**Limitations** (noted honestly as portfolio context):
- Simulated data, not real sensor readings
- No raw vibration data; Torque used as proxy for electrical stress
- Represents a single machine/process scenario, not generalizable to all equipment types

**Class imbalance:** ~3.4% failure rate (339 out of 10,000 rows), reflecting real-world maintenance scenarios.

## Approach

### Two-Layer Detection

| Layer | Model | Type | What it does |
|-------|-------|------|-------------|
| 1 | **XGBoost** | Supervised classification | Predicts known failure types with `scale_pos_weight` to handle imbalance |
| 2 | **Isolation Forest** | Unsupervised anomaly detection | Trained only on normal data; detects patterns outside labeled failure types |

### Risk Logic

| Color | Condition |
|-------|-----------|
| 🔴 **Red** | XGBoost predicts failure |
| 🟡 **Yellow** | XGBoost says normal, but anomaly score is in the bottom 5% (unusual pattern) |
| 🟢 **Green** | Both models agree normal |

### Why These Models?

- **XGBoost** over Random Forest — better handling of imbalanced data via `scale_pos_weight`, standard in ML competitions and industry
- **Isolation Forest** over One-Class SVM — scales linearly with sample size, works well on high-dimensional tabular data, requires no distributional assumptions
- Classical ML over deep learning — faster to train, easier to explain in interviews, sufficient for tabular data of this scale

## Results

### Classification Metrics (XGBoost on test set)

| Class | Precision | Recall | F1-score | Support |
|-------|-----------|--------|----------|---------|
| Normal | 0.99 | 0.99 | 0.99 | 1,932 |
| Failure | **0.72** | **0.78** | **0.75** | 68 |
| **Accuracy** | | | **0.98** | 2,000 |

### Confusion Matrix

```
              Predicted
              Normal  Failure
Actual Normal   1911       21
       Failure    15       53
```

Recall (78%) is prioritized over precision — false negatives (missed failures) have higher cost in maintenance scenarios.

### Risk Distribution (test set)

- 🟢 Green: 1,841 / 2,000 (92.1%)
- 🟡 Yellow: 85 / 2,000 (4.2%)
- 🔴 Red: 74 / 2,000 (3.7%)

## Local Setup

```bash
# Clone the repository
git clone https://github.com/YOUR_USERNAME/predictive-maintenance-ml.git
cd predictive-maintenance-ml

# Create virtual environment (Python 3.13+)
python -m venv venv
.\venv\Scripts\activate   # Windows
# source venv/bin/activate  # Linux/macOS

# Install dependencies
pip install -r requirements.txt

# Run preprocessing + training (optional — models are pre-trained)
python -m src.preprocessing
python -m src.train_classifier
python -m src.train_anomaly
python -m src.evaluate

# Launch dashboard
streamlit run app.py
```

## What I Learned

- Handling severe class imbalance (~3% failure rate) with `scale_pos_weight` and stratified splitting
- Combining supervised and unsupervised models for a more robust risk assessment
- Isolation Forest as a practical method for detecting unseen failure patterns
- Building real-time simulation dashboards with Streamlit + Plotly
- Why recall/F1 matter more than accuracy in maintenance scenarios
